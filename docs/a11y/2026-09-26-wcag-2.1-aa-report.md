## Failures to fix

### 1. Demo chat history is not keyboard-scrollable

- **Criterion:** WCAG 2.1.1 Keyboard (A). Axe also tags this rule as 2.1.3.
- **Impact:** serious
- **Rule:** `scrollable-region-focusable`
- **Where:** `/app`, after the scripted demo has enough messages to overflow a chat log
- **Element:** `div.chat-log` in `apps/web/src/components/MvpDemo.tsx` (family group log and private log). Both use `overflow: auto` and `max-height: min(26rem, 52vh)` in `apps/web/src/components/MvpDemo.css`.
- **When it fails:** after “Send the photo” → “Yes, I’ll take part” → “A little later — bring it back”, and again after “Use a sample line” and after “Yes, share it”. The empty first paint passes, which is why `pnpm a11y:web` stays green.
- **What axe said:** the scrollable region has no focusable content and is not itself focusable, so a keyboard user cannot move through the history.
- **Fix:** on each `.chat-log`, set `tabIndex={0}` and an accessible name such as “Family group messages” and “Private messages”. Keep `role="log"`. Then extend `apps/web/scripts/a11y-check.mjs` to walk those demo steps so this cannot regress unseen.

### 2. Homepage footer forces horizontal scrolling at 320px

- **Criterion:** WCAG 1.4.10 Reflow (AA). Content should fit a 320 CSS-pixel wide viewport without two-axis scrolling.
- **Impact:** serious for the public homepage. Axe has no rule for this, so the gate does not catch it.
- **Where:** `/` only. Measured `documentElement.scrollWidth` 495 against a 320px viewport.
- **Element:** footer `nav` inside `apps/web/src/pages/index.astro`, styled by `.slate-footer nav` in `apps/web/src/components/designs/slate/slate.css` (`display: flex; gap: 1rem` with no wrap). The links through “Sitemap” extend to x = 495.
- **Checked and clear at 320px:** `/how-it-works`, `/app`, `/family`, `/my-data`, `/privacy`, `/terms`, `/cookies`, `/sitemap`, `/404`, and `/designs/slate`, `/designs/linen`, `/designs/quiet`, `/designs/mist`, `/designs/ink`.
- **Fix:** give `.slate-footer nav` `flex-wrap: wrap` and a row gap, the same pattern as `.site-footer nav` in `apps/web/src/styles/tokens.css`.

### 3. Ink design index numbers miss contrast

- **Criterion:** WCAG 1.4.3 Contrast (Minimum) (AA)
- **Impact:** serious
- **Rule:** `color-contrast`
- **Where:** `/designs/ink` only, with the consent banner open and after it is dismissed. This route is a design study. It is not in the sitemap and not in `a11y-check.mjs`.
- **Element:** `.ink-action-index` in `apps/web/src/components/designs/ink/ink.css` (`opacity: 0.55` on `--ink: #0a0a0a`). Three visible labels, “01”, “02”, and “03”, are `aria-hidden` and still painted.
- **Measured:** foreground `#787878` on `#ffffff`, 12px normal weight, ratio **4.41:1**. AA for that size is **4.5:1**.
- **Other design routes** (`/designs/slate`, `/designs/linen`, `/designs/quiet`, `/designs/mist`) had 0 axe violations on the same tags.
- **Fix:** drop the opacity and set a solid color at or above 4.5:1, for example `#5c5c5c`.

## Reviewed, and not a WCAG 2.1 A/AA failure

**Color contrast on the public pages.** Axe marked `color-contrast` incomplete on the BaseLayout pages because `body` in `tokens.css` uses two radial gradients, so it would not compute a single background. The same happened for a few lines on `/designs/quiet`. Manual ratios for the tokens in use:

All of those clear 4.5:1. No public-page contrast change is required from this audit.

**Signed-out `/family` and `/my-data` have no `h1`.** The visible heading is the `h2` “Get started with Telegram” in `apps/web/src/components/TelegramLogin.tsx`. Requiring an `h1` is an axe best-practice check, not a WCAG 2.1 A/AA failure. Optional follow-up: use an `h1` for that heading on those two pages. The signed-in family record and the download/delete controls were not opened; they need a Telegram `id_token`.

**Telegram’s login window** stays out of scope. The site already says so in the footer and on `/sitemap`.

**Heading order** on the scanned routes did not skip levels. Each public page has `lang="en"` and a `main` landmark. `/family` and `/my-data` are the pages whose first heading is an `h2`.
