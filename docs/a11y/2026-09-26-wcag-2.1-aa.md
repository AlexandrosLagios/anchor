## Confirmed failures to fix

### 1. Primary buttons inside `.prose` are invisible — 1.4.3 Contrast (AA)

`.prose a` in `apps/web/src/styles/tokens.css` (specificity 0,1,1) overrides `.btn-primary` (0,1,0). The link text and the button fill are both `#c9a77a` / `rgb(201, 167, 122)`. Contrast ratio is 1:1. axe lists this as incomplete (“Element has a 1:1 contrast ratio with the background”), so `pnpm a11y:web` stays green.

Affected controls:

- `/how-it-works` — `a.btn.btn-primary` “Get started” (`apps/web/src/pages/how-it-works.astro`)
- `/404` — `a.btn.btn-primary` “Back to Anchor” (`apps/web/src/pages/404.astro`)

The secondary links on those pages (`a.btn.btn-secondary`) are also recolored to `#c9a77a`. On the page background `#1a1a1a` that ratio is 7.70:1, so they still pass 1.4.3. Set their color explicitly anyway, or the same override will hide them if the fill ever matches the brand color.

Intended primary button (used on the homepage and the consent banner, and passing): text `#1a1a1a` on fill `#c9a77a`, ratio 7.70:1.

Fix in `apps/web/src/styles/tokens.css`: give `.prose a.btn-primary` color `#1a1a1a`, and `.prose a.btn-secondary` / `.prose a.btn-quiet` color `var(--ink)`, including the hover states. Re-check `/how-it-works` and a missing URL (the 404 page).

### 2. Demo chat history cannot be scrolled from the keyboard — 2.1.1 Keyboard (A)

On `/app`, after the scripted conversation grows, the private `.chat-log` (`apps/web/src/components/MvpDemo.tsx`, the “Nikos, in private” pane) is a nested scroller:

- `overflow-y: auto`, `max-height: min(26rem, 52vh)` (`apps/web/src/components/MvpDemo.css`)
- Measured after “Send the photo” → “Yes, I’ll take part” → “A little later — bring it back” → “Use a sample line”: `scrollHeight` 1330, `clientHeight` 416
- No `tabindex`. `tabIndex` is `-1`, so the log is not in the tab order
- `scrollTop` can be set from script (0 → 200 sticks). ArrowDown / PageDown do nothing until the element is made focusable
- With `tabindex="0"` and focus on the log, PageDown moved `scrollTop` from 0 to 55

The latest line stays in view because a `useEffect` scrolls the log to the bottom when `lines` changes. Earlier messages sit above that window. Page scroll does not move the inner log. Sighted keyboard users cannot reach them. Screen-reader users can still walk the `role="log"` content.

Fix: set `tabIndex={0}` on both `.chat-log` elements (group and private) and give each an accessible name (the pane heading is a reasonable `aria-labelledby` target). `:focus-visible` in `tokens.css` already draws a 2px `#e0c49a` outline. Confirm ArrowDown / PageDown change `scrollTop` after the private log exceeds its max height. Do not rely on the axe gate for this; `scrollable-region-focusable` is outside the WCAG tag set used here.

Routes: `/`, `/how-it-works`, `/app`, `/family`, `/my-data`, `/privacy`, `/terms`, `/cookies`, `/sitemap`, and an unknown URL that renders `404.astro`. Each was audited with the consent banner open and after Accept, except the extra `/family` states below, which were audited after Accept.

- axe WCAG 2.1 A/AA violations: none on those routes, including `/family` on “Create an account” and on “Sign in”
- 1.4.10 Reflow at 320×640: no horizontal scroll on the public routes. The create-account form at 320px also stays within the viewport (`scrollWidth` 320)
- 1.4.12 Text spacing (line-height 1.5, letter-spacing 0.12em, word-spacing 0.16em, paragraph spacing 2em): no extra horizontal scroll and no clipped `overflow: hidden` text on the public routes
- 2.4.1 Bypass blocks: “Skip to content” is the first tab stop on `/` and becomes visible with a 2px outline
- 2.4.7 Focus visible: sampled tab stops on `/` and the create-account form use `outline: solid 2px rgb(224, 196, 154)`
- Consent banner contrast, measured because axe could not resolve the background (the banner overlaps the page): body text `#c4bfb5` on `#111` is 10.31:1; title `#f2f0eb` on `#111` is about 15:1; “Accept” is the passing primary button above. Not a failure

## Design prototypes (`/designs/*`)

These URLs are built and publicly reachable. They are not in the header, footer, or sitemap. The live homepage is the slate layout inside `BaseLayout` (tokens plus `slate.css`) and did pass. `/designs/slate` is a separate page that only loads `slate.css`.

### `/designs/slate` — 1.4.3 and 1.4.10

axe violations (serious), light text on a white page. This page never sets the dark background the slate tokens assume:

| Element | Foreground | Background | Ratio | Needed |
| --- | --- | --- | --- | --- |
| `#slate-brand` | `#f2f0eb` | `#ffffff` | 1.13 | 3:1 (large text) |
| `.slate-line` | `#f2f0eb` | `#ffffff` | 1.13 | 3:1 (large text) |
| `.slate-support` | `#c4bfb5` | `#ffffff` | 1.83 | 4.5:1 |
| `.slate-btn-ghost` | `#f2f0eb` | `#ffffff` | 1.13 | 4.5:1 |
| `.slate-link` | `#c9a77a` | `#ffffff` | 2.26 | 4.5:1 |

Reflow at 320px: document `scrollWidth` 374 vs `clientWidth` 320. `a.slate-btn` is 346px wide (`right` edge 374). `slate.css` does not set `box-sizing: border-box` (that rule lives in `tokens.css`, which this page does not import), and under 480px `.slate-btn` is `width: 100%`.

Fix: give the page the same dark background as the live site (`#1a1a1a`) or retoken the colors for white, and set `box-sizing: border-box` so the 320px layout does not overflow. Re-run axe on `/designs/slate` after that; several of the contrast failures should disappear once the background is dark.

### `/designs/ink` — 1.4.3

`.ink-action-index` (`apps/web/src/components/designs/ink/ink.css`, `opacity: 0.55`) renders as `#787878` on `#ffffff`, ratio 4.41:1. Small text (12px) needs 4.5:1. Three nodes: the `01` / `02` / `03` indexes. `aria-hidden="true"` hides them from assistive tech; it does not exempt them from visual contrast.

Fix: raise the opacity or set a solid color at or above 4.5:1 against `#ffffff`. 320px reflow passed.

### `/designs/linen` and `/designs/mist`

No axe WCAG 2.1 A/AA violations. No horizontal scroll at 320px.

### `/designs/quiet` — unresolved

axe incomplete on six nodes: background is a gradient, so the contrast ratio was not computed. Not recorded as a pass or a fail. Check the hero text against the lightest and darkest gradient stops before shipping this page.

## Suggested order of work

1. `.prose a.btn-primary` color override (`tokens.css`). This is on two live pages and the label is currently unreadable.
2. `tabindex="0"` and an accessible name on `.chat-log` (`MvpDemo.tsx`). Confirm keyboard scrolling after the private conversation grows.
3. Design prototypes only if those URLs stay deployed: slate background and box-sizing, ink index contrast, then a manual pass on the quiet gradient.
