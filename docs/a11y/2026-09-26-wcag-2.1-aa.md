# WCAG 2.1 AA report — Anchor website

Audit date: 2026-09-26  
Commit: `d643ab4043e3f866eb1be9d2df7b384ff4a0a0e4` (Midnight Sprint brand kit on `main`)  
App: `apps/web` static preview (`astro build` + `astro preview` at `http://127.0.0.1:4321`)  
Engine: axe-core 4.13.0, tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, headless Chrome via Playwright `channel: 'chrome'`

## Verdict

The site does **not** pass WCAG 2.1 Level AA.

`pnpm a11y:web` (`apps/web/scripts/a11y-check.mjs`) would still exit 0. That script only fails on axe **violations**, at the default viewport, on the ten public routes, with the consent banner open and dismissed. It does not resize, open the demo, or turn on the Accessibility widget. The failures below are either axe `incomplete` results, or they appear only after those extra states.

Machine-readable twin: [`2026-09-26-wcag-2.1-aa.json`](./2026-09-26-wcag-2.1-aa.json).

## How it was run

- 10 public routes: `/`, `/how-it-works`, `/app`, `/family`, `/my-data`, `/privacy`, `/terms`, `/cookies`, `/sitemap`, and a missing URL that renders `404`.
- Design studies (built, not in the nav): `/designs/slate`, `/designs/ink`, `/designs/linen`, `/designs/mist`, `/designs/quiet`.
- Viewports: 1280×900 and 320×800 (1.4.10 reflow). Demo path also at 390px wide, under the 52rem chat breakpoint.
- Consent banner open and dismissed (`localStorage` key `anchor-consent-v1`).
- Extra states: demo through “Use a sample line”; family choose / create-account / sign-in; Accessibility panel open; High contrast; High contrast plus Largest text.
- Keyboard sample: eight Tab stops from the top of `/` at 1280.

Signed-in family record, memory upload, and the Telegram login popup were not exercised. The popup is Telegram’s UI.

## Failures to fix (published pages)

### 1. 1.4.3 Contrast — primary buttons inside `.prose` are unreadable (serious)

“Get started” on `/how-it-works` and “Back to Anchor” on the 404 page render as `#443dff` on `#443dff` (1:1).

`.prose a` in `apps/web/src/styles/tokens.css` sets `color: hsl(var(--primary))`. That selector (one class + one element) beats `.btn-primary` (one class), so the button label matches the button fill. Axe files this as **incomplete**, not a violation, which is why the gate stays green. It is still a 1.4.3 failure: the label is invisible.

Secondary buttons in the same paragraphs stay readable (about 4.66:1, `#443dff` on `#dddbff`). Inline prose links such as “My data” are about 6.06:1 on the page background.

**Fix:** keep `.prose a` from painting button text. For example, reset color on `.prose a.btn` so `.btn-primary` / `.btn-secondary` win. Pages: `apps/web/src/pages/how-it-works.astro`, `apps/web/src/pages/404.astro`.

### 2. 1.4.3 Contrast — “Voice note” (serious)

After “Use a sample line” on `/app`, `.voice-tag` is `#443dff` on `#cbc8ff`, **3.94:1**. Text is 12.48px bold, so the AA bar is 4.5:1.

Source: `.heart, .voice-tag { color: var(--brand); }` in `apps/web/src/components/MvpDemo.css`. The tag sits on the light accent bubble.

**Fix:** use the text or highlight token for that label so the ratio clears 4.5:1 on the bubble.

### 3. 2.1.1 Keyboard — private chat log scrolls with no focus stop (serious)

On `/app`, after “Yes, I’ll take part”, the private `.chat-log` overflows (`scrollHeight` 645 vs `clientHeight` 416 at 1280; worse after “bring it back”). `overflow` is `auto` and `tabIndex` is `-1`. Axe rule `scrollable-region-focusable` (2.1.1, Level A). Same at 390px. The group log does not overflow in this script, so it does not fail.

Source: `apps/web/src/components/MvpDemo.tsx` (the `role="log"` div) and `.chat-log` in `MvpDemo.css`.

**Fix:** make a scrollable log keyboard-focusable (`tabIndex={0}`) and give it an accessible name. Do not rely on arrow keys that never land there.

`.family-chat-log` in `apps/web/src/components/FamilyRecord.css` uses the same pattern (`max-height` + `overflow: auto`). This run could not fill it (no signed-in API). Treat it as the same fix when the log grows past the box.

### 4. 1.4.3 Contrast — High contrast setting fails (serious)

Turning on Accessibility → High contrast (`html.a11y-contrast` in `apps/web/src/styles/tokens.css`) fails AA on `/`:

| What | Ratio | Colors | Why |
| --- | --- | --- | --- |
| Header, footer, and “Get started” links | 3.25:1 | `#443dff` on `#050316` | `html.a11y-contrast a` forces primary blue on the dark page. 15px text needs 4.5:1. |
| “Start Remembering Together” | 3.26:1 | `#050316` on `#443dff` | Button text is the dark background token on primary blue. |
| Skip link, when focused | 1:1 | `#443dff` on `#443dff` | `.slate-skip` sets a light label, then `html.a11y-contrast a` overrides it to primary. |
| Text-size “Larger” / “Largest”, and “Reset all” | 1.30:1 | `#fbfbfe` on `#dddbff` | Text flips to the light token; accent / soft backgrounds stay light purple. |
| Active “Default” text-size chip | 3.26:1 | `#050316` on `#443dff` | Same pair as the primary button. |

Axe reported 20 contrast nodes on `/` in this state (nav, auth link, primary button, in-page links, footer). The skip link and widget chips were measured from computed style; axe’s stored sample was truncated at 8 nodes per rule.

**Fix:** high contrast needs pairs that clear 4.5:1, not a swap that leaves primary blue and accent purple in place. Link color must not override the skip link or buttons. Secondary and scale buttons need a dark background or a dark label once the page background goes dark. Widget styles: `apps/web/src/components/AccessibilityWidget.css`.

## Design studies (lower priority)

These routes are in the static build and are not linked from the shell nav.

- **`/designs/ink` — 1.4.3.** `.ink-action-index` is `#787878` on `#ffffff`, **4.41:1** (12px, needs 4.5:1), from `opacity: 0.55` in `apps/web/src/components/designs/ink/ink.css`. `aria-hidden` does not exempt visible text.
- **`/designs/slate` — 1.4.10.** At 320px the page scrolls horizontally (`scrollWidth` 352, `main.slate-main` about 344). Published pages that share `slate.css` did not overflow.
- **`/designs/quiet`.** Axe could not score text on the gradient (`incomplete`). Not recorded as a failure.
- **`/designs/linen` and `/designs/mist`.** 0 axe violations at 1280 and 320.

## What passed

Published routes at 1280 and 320, consent open and dismissed, had **0 axe violations** before any demo clicks. That includes `/family` on choose, create-account, and sign-in.

- `lang="en"`, a unique document title, one skip link to `#main`, and a `main` landmark on the shell.
- Heading order does not skip on the pages that have headings. `/my-data` while signed out starts at an `h2` (“Get started with Telegram”) because the `h1` only renders after a Telegram session.
- First eight Tab stops on `/`: Skip to content, Anchor, How it works, Try the demo, Family, Privacy, Get started, Start Remembering Together. Focus ring is 2px solid `rgb(68, 61, 255)`.
- No horizontal overflow at 320px on the published routes (1.4.10 for the unsigned pages).
- Primary hero buttons outside `.prose` are about 6.06:1 (`#fbfbfe` on `#443dff`). Body copy at 78% opacity of the text token is still about 19.7:1 on the page background.
- Demo mobile tab (selected) is about 6.12:1 (`#f4fffc` on `#443dff`). Speaker names on the bubbles are about 7.0:1 or higher. Both were failures before this brand kit.
- Family registration says “Step 1 of 3” and lists Account, Group, Family.
- Logo image is `alt=""` beside the visible word “Anchor”.

## Out of scope for this run

- Signed-in `/family` (record, upload, Ask). `input.reg-file` width at 320px was a previous failure and was not rechecked.
- Browser zoom to 200% as its own pass. Reflow was checked by loading at 320px wide.
- Screen reader behavior, beyond the accessibility tree checks axe performs.
- WCAG 2.1 AAA (including 2.5.5 target size). Sample primary controls are 44px tall via `--tap: 2.75rem`.
