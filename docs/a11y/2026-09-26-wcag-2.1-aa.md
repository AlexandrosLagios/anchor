# WCAG 2.1 AA audit

Date: 2026-09-26. Commit: `aa4312e9ea1df2fa8b6bb67425fc3cf1fda17d42` (main, "Confine messenger names to Connections on the family page."). Tool: axe-core 4.13.0 in Playwright Chromium, tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`. Server: production build via `astro preview` at `http://127.0.0.1:4321`.

This report is the backlog. It does not change the site.

## Result

`pnpm a11y:web` (`apps/web/scripts/a11y-check.mjs`) passes: 10 public routes, consent banner open and dismissed, 0 axe violations.

The site does not yet conform to WCAG 2.1 Level AA. Two contrast failures (success criterion 1.4.3) are real. One of them is filed by axe as `incomplete`, so the gate exits 0.

## Confirmed failures

### 1. Primary link buttons inside `.prose` are invisible (1.4.3, serious)

axe id: `color-contrast`. Ratio: 1:1. Foreground and background are both `rgb(68, 61, 255)` (`hsl(var(--primary))`). A pixel sample of the rendered control is a solid purple rectangle. The label is not readable.

| Page | Control | Selector |
| --- | --- | --- |
| `/how-it-works` | Get started | `a.btn.btn-primary[href="/family"]` |
| `/404` | Back to Anchor | `a.btn.btn-primary[href="/"]` |

Seen at 1280px and 390px, with the consent banner open and dismissed.

Cause: `.prose a` in `apps/web/src/styles/tokens.css` (specificity 0,1,1) is later than `.btn-primary` (0,1,0) and sets `color: hsl(var(--primary))` on a control whose background is the same token.

`.prose a` at `apps/web/src/styles/tokens.css` (around lines 383-386):

```css
.prose a {
  color: hsl(var(--primary));
  font-weight: 600;
}
```

`.btn-primary` in the same file (around lines 313-318):

```css
.btn-primary,
.slate-btn-primary {
  background: hsl(var(--primary));
  color: hsl(var(--background));
  border-color: hsl(var(--primary));
}
```

Why the gate stayed green: axe put this node in `incomplete` ("Element has a 1:1 contrast ratio with the background"), not in `violations`. `apps/web/scripts/a11y-check.mjs` only fails the build on `violations`.

Later fix: a more specific rule for button links, including hover, so the label stays `hsl(var(--background))`. For example `.prose a.btn-primary`. Keep the five brand colors.

### 2. High contrast mode fails 1.4.3 on every public page (serious)

State: consent dismissed, `html.a11y-contrast` and `html.a11y-text-150` (the classes the Accessibility panel adds for High contrast and Largest). axe reports these as violations. 159 nodes across the 10 routes.

Every page shares 13 nodes at 3.25:1: header nav links, footer links, and Get started (`.auth-nav-link`). Foreground `#443dff`, background `#050316`, 18.75px, weight 600. Large text needs 3:1 only at 18pt (24px) or 14pt (18.67px) bold. These are under that, so the bar is 4.5:1.

Extra nodes on top of those 13:

| Page | Extra | Ratio | What |
| --- | --- | --- | --- |
| `/how-it-works` | 2 | 3.25:1 | In-page link “My data” (22.5px). “Get started” label is dark `#050316` on purple `#443dff`. |
| `/app` | 10 | 1.21:1 | Promise chips, both panel headings, both empty chat lines. Foreground `#f3f2fe` on `#dddbff`. |
| `/family` | 2 | 3.25:1 and 1.29:1 | Current step “Account” (22.5px, purple on dark). “Sign in” (`.btn-secondary`) is `#fbfbfe` on `#dddbff`. Bold 18.75px, so the bar is 3:1, and 1.29 fails it. |
| `/privacy` | 5 | 3.25:1 | In-page links, 22.5px, purple on dark. |
| `/sitemap` | 9 | 3.25:1 | In-page links, 22.5px, purple on dark. |
| `/404` | 1 | 3.25:1 | “Back to Anchor” is dark on purple. |
| `/`, `/my-data`, `/terms`, `/cookies` | 0 |  | Chrome links only. |

With the panel actually open on `/` (not only the classes), the text-size controls also fail:

| Target | Ratio | Foreground | Background | Need |
| --- | --- | --- | --- | --- |
| Default and Larger | 1.29:1 | `#fbfbfe` | `#dddbff` | 4.5:1 |
| Largest (`.is-active`) | 3.25:1 | `#050316` | `#443dff` | 4.5:1 |

Cause, in the high-contrast token swap (`apps/web/src/styles/tokens.css`, `html.a11y-contrast`):

- `--background` becomes the dark color and `--text` becomes the light page color.
- Links are forced to `hsl(var(--primary))`, which is 3.25:1 on that dark page. In-page links at 22.5px are still normal text (not bold).
- `.btn-primary` uses `color: hsl(var(--background))`. After the swap, that label is dark on brand purple (3.25:1).
- `.btn-secondary` and the text-size buttons use a light label on `var(--soft-bg)` / accent (`#dddbff`). `--ink` follows the flipped `--text`. `--soft-bg` stays light. Light on light is about 1.2:1. Widget rules are in `apps/web/src/components/AccessibilityWidget.css`.

Later fix: choose high-contrast link and button pairs that clear 4.5:1, still using only the five brand colors. Do not use the flipped `--background` as the label color on a purple fill. Do not leave accent fills light while text flips light.

### 3. Demo, after “Use a sample line” (serious)

Route `/app`, default theme, consent dismissed. Path: “Send the photo”, “Yes, I’ll take part”, “A little later — bring it back”, “Use a sample line”. These two are axe violations, so a check of that state would fail the gate. The current gate never clicks through the demo.

| Rule | WCAG | Target | Detail |
| --- | --- | --- | --- |
| `color-contrast` | 1.4.3 AA | `.voice-tag` “Voice note” | 3.94:1. Foreground `#443dff` (`var(--brand)`), background `#cbc8ff`. 12.48px bold, so 4.5:1 is required. Style: `apps/web/src/components/MvpDemo.css` (`.voice-tag` and the bubble behind it). |
| `scrollable-region-focusable` | 2.1.1 A | Private `.chat-log` (`role="log"`) | The log scrolls and is not in the tab order. Keyboard users cannot move it. `overflow: auto` is on `.chat-log` in `MvpDemo.css`. |

Later fix: darken or enlarge the voice-note label until it clears 4.5:1 against the bubble. Make a scrollable `.chat-log` focusable (`tabIndex={0}`) and give it an accessible name. The group log uses the same class and will hit the same rule once it overflows.

Checked marks in the demo rail (`.mvp-rail-mark`, `aria-hidden`) and some bubble names were axe `incomplete` (non-text glyphs, or a background axe could not sample). Not counted as failures.

## What passed

axe violations: 0 on every row below, except the high-contrast row in the previous section.

Routes: `/`, `/how-it-works`, `/app`, `/family`, `/my-data`, `/privacy`, `/terms`, `/cookies`, `/sitemap`, and a missing URL that renders `/404`.

States:

- Consent banner open, and consent dismissed. Viewports 1280×800 and 390×844.
- Accessibility panel open (consent dismissed, desktop) on `/`, `/app`, `/family`, `/my-data`, before any high-contrast toggle. No violations.
- `pnpm a11y:web` on the same routes and both consent states: `axe WCAG 2.1 AA: 10 routes × 2 consent states — 0 violations`.
- At 320px wide, none of those routes overflowed horizontally (`scrollWidth` stayed within `clientWidth`).

`/404` returns HTTP 404 and still rendered a page axe could check.

## Incomplete checks that are not failures

- `#consent-body` on pages with the banner open. axe could not sample the background because the fixed banner overlaps the page. Declared text is `hsl(var(--text) / 0.72)` on `hsl(var(--background))`. Composited, that is about 8.6:1.
- Home page step numbers `1` `2` `3` (`.slate-step-num`, `aria-hidden="true"`) under high contrast. axe said the text was too short to judge. They are decorative.

## Out of scope

- `/designs/ink`, `/designs/linen`, `/designs/mist`, `/designs/quiet`, `/designs/slate` are not linked from the public chrome. Not audited.
- No manual pass for keyboard order, keyboard traps, screen reader names, or reflow at 200% zoom. axe does not cover every WCAG 2.1 criterion.
- Telegram login windows are third-party. The footer already says they are outside this site.

## Reproduce

```bash
pnpm build:web
pnpm exec astro preview --root apps/web --host 127.0.0.1 --port 4321
pnpm a11y:web
```

The gate will stay green until it also fails on `color-contrast` nodes that axe leaves in `incomplete` with a measured ratio. The invisible buttons are that case.
