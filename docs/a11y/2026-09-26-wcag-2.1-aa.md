## Fixes, in order

### 1. Primary buttons inside `.prose` are the same blue as their fill

- Criterion: 1.4.3 Contrast (Minimum), AA
- Impact: serious. Ratio 1:1
- Pages: `/how-it-works` “Get started”, `/404` “Back to Anchor”
- axe: **incomplete**, not a violation. Message: background could not be determined because the element overlaps other elements. Computed style still shows the failure.

`apps/web/src/pages/how-it-works.astro` (the link in the closing paragraph) and `apps/web/src/pages/404.astro` put `<a class="btn btn-primary">` inside `<article class="prose">`.

`apps/web/src/styles/tokens.css`:

- `.prose a` sets `color: hsl(var(--primary))` (specificity 0,1,1)
- `.btn-primary` sets `color: hsl(var(--background))` (specificity 0,1,0)

The link rule wins. Computed color and background are both `rgb(68, 61, 255)` (`#443dff` on `#443dff`).

Hover is fine, because `.btn-primary:hover` is stronger and sets a light label on `#2f27ce`. The label is invisible until hover.

The secondary links in those same paragraphs (“Try the scripted demo”, “Open the demo”) have the same bug. They currently pass at 4.66:1 (`#443dff` on `#dddbff`) and should be restored with the primary buttons.

Smallest fix: give button links a color rule that beats `.prose a`, including hover.

```css
.prose a.btn-primary { color: hsl(var(--background)); }
.prose a.btn-secondary { color: hsl(var(--text)); }
```

Keep the existing hover rules. After the change, re-run axe on `/how-it-works` and `/404` with the consent banner dismissed. The primary link should be about 6:1 (light label on `#443dff`).

### 2. High contrast plus largest text fails on every public page

- Criterion: 1.4.3 Contrast (Minimum), AA
- Impact: serious
- State: Accessibility panel, High contrast on, text size Largest (`html.a11y-contrast.a11y-text-150`)
- axe: **violation** `color-contrast`, 159 nodes across the 10 public routes

The ratios are color failures. 3.25:1 is under the 3:1 large-text floor, so leaving text at 100% does not clear the link failures.

Three mechanisms, all in `apps/web/src/styles/tokens.css` under `html.a11y-contrast`:

1. Chrome links and in-content links are `#443dff` on `#050316` (3.25:1). The block sets `a` (and the nav and footer links) to `hsl(var(--primary))` while `--background` is the dark color. About 13 nodes per page are the header and footer links. Body links on `/how-it-works`, `/privacy`, and `/sitemap` match. The registration step on `/family` matches.
2. Primary buttons are `#050316` on `#443dff` (3.25:1). `html.a11y-contrast .btn-primary` sets `color: hsl(var(--background))`, and high contrast swaps `--background` to the dark color. Seen on “Get started” and “Back to Anchor”.
3. Light text sits on lavender surfaces that high contrast does not remap. `--accent` stays `#dddbff`.
   - `/app` rail chips, panel headings, and empty states: `#f3f2fe` on `#dddbff` (1.21:1)
   - `/family` “Sign in” (`.btn-secondary`): `#fbfbfe` on `#dddbff` (1.29:1). Bold 18.75px, so the floor is 3:1

Fix direction: in high contrast, links and primary-button labels need a light color that stays light (the swapped `--text`, not the swapped `--background`). Text on `--accent` panels and secondary buttons needs the dark color, or those surfaces need to become the dark background. Stay inside the five brand colors.

Re-test with consent dismissed and this `localStorage` value set before load (`anchor-a11y-prefs-v1`):

```json
{"textScale":150,"highContrast":true,"spacing":false,"underlineLinks":false,"readableFont":false,"reduceMotion":false,"bigCursor":false,"grayscale":false,"hideImages":false}
```

### 3. Demo, after “Use a sample line”

Page: `/app`. Clicks, in order: “Send the photo”, “Yes, I’ll take part”, “A little later — bring it back”, “Use a sample line”. Default theme.

**1.4.3 Contrast (Minimum).** One node.

`.voice-tag` in `apps/web/src/components/MvpDemo.tsx` (`Voice note`) is `color: var(--brand)` in `apps/web/src/components/MvpDemo.css`. It sits on a Nikos bubble, `background: var(--bubble-athina)` (`primary` at 12% opacity), which composites to about `#cbc8ff`. Result: `#443dff` on `#cbc8ff`, 12.48px bold, 3.94:1. Needs 4.5:1. `.heart` uses the same color rule. Recheck it if that span is on screen.

**2.1.1 Keyboard (A).** Also tagged 2.1.3 (AAA). axe rule `scrollable-region-focusable`. One node.

The private `.chat-log` (`role="log"`) in `MvpDemo.tsx` overflows (`overflow: auto` in `.chat-log`) and has no focusable content, so a keyboard user cannot scroll it. Give both chat logs `tabIndex={0}` and a name (the panel heading is a reasonable name), or stop the region from scrolling until it contains a focusable control.

### 4. Ink design study step numbers

- Criterion: 1.4.3 Contrast (Minimum), AA
- Route: `/designs/ink` only. Not linked from the public nav. Not in `pnpm a11y:web`.
- axe: **violation**, desktop and 320px, both consent states

`.ink-action-index` in `apps/web/src/components/designs/ink/ink.css` sets `opacity: 0.55` on 12px text. The indexes 01, 02, and 03 composite to `#787878` on `#ffffff`, 4.41:1. They are `aria-hidden`, and they are still visible text, so 1.4.3 applies. Raise the opacity, or set a solid color that clears 4.5:1. The elements are in `apps/web/src/pages/designs/ink.astro`.
