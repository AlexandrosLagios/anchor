# WCAG 2.1 AA audit — Anchor website

Date: 2026-09-26  
Commit: `98c38267ba473a684cf24d111027bc93a5e9e7a8` (`Show the full privacy policy when creating an account.`)  
Target: static preview of `apps/web` (`astro build` then `astro preview` on `http://127.0.0.1:4321`).  
Level: WCAG 2.1 Level A and Level AA.

## Result

The shipping site does **not** pass WCAG 2.1 AA.

`pnpm a11y:web` (`apps/web/scripts/a11y-check.mjs`) reports **0 axe violations** across 10 public routes × 2 consent states. That gate only fails on axe `violations`. The broken buttons below are axe `incomplete` results, so the gate stays green.

Two controls on pages in the sitemap have a contrast ratio of **1:1**. Design URLs that are built but not linked from the sitemap fail contrast, and one of them fails reflow.

The new account-creation privacy policy (this commit) passes the checks below.

## How this was tested

- axe-core 4.13, tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, on first paint with the cookie banner open and with it dismissed.
- A separate contrast walk: text color composited over ancestor backgrounds. Large text uses 3:1; other text uses 4.5:1. Disabled controls were skipped (exempt under 1.4.3).
- Reflow at 320×640 CSS pixels (1.4.10): horizontal overflow of the document.
- Signup: open `/family`, choose **Create an account**, run axe and the contrast walk, scroll the policy end into view, then repeat reflow at 320px.
- Demo chat: drive `/app` until the private log overflows, then Tab to it and press Page Down in headed Chromium 153.

Routes: `/`, `/how-it-works`, `/app`, `/family`, `/my-data`, `/privacy`, `/terms`, `/cookies`, `/sitemap`, a missing URL (404), `/designs/slate`, `/designs/ink`, `/designs/linen`, `/designs/mist`, `/designs/quiet`.

## Failures to fix

### 1. Primary buttons inside `.prose` are the same color as their background

- **Criterion:** 1.4.3 Contrast (Minimum), Level AA. Serious.
- **Where:**
  - `/how-it-works` — “Get started” (`apps/web/src/pages/how-it-works.astro`, the `a.btn.btn-primary` in the closing paragraph).
  - `/404` — “Back to Anchor” (`apps/web/src/pages/404.astro`).
- **Measured:** `color: rgb(201, 167, 122)` on `background: rgb(201, 167, 122)`. Ratio **1.00**. Required **4.5:1** (16px, weight 600).
- **Cause:** `.prose a` in `apps/web/src/styles/tokens.css` sets `color: var(--brand)` and beats `.btn-primary` (one class + one element versus one class). The button background stays `--brand` (`#c9a77a`). The label disappears.
- **Why the gate misses it:** axe lists `.btn-primary` as color-contrast **incomplete**, not as a violation. `apps/web/scripts/a11y-check.mjs` ignores incomplete results.
- **Fix:** Stop the prose link color from applying to buttons. For example, change `.prose a` to `.prose a:not(.btn)` so `.btn-primary` keeps `color: #1a1a1a` and `.btn-secondary` keeps `color: var(--ink)`.
- **Check after the fix:** both labels must be at least 4.5:1, and axe should no longer leave `.btn-primary` incomplete on those two URLs.

The secondary links next to them (“Try the scripted demo”, “Open the demo”) stay readable. Their text also comes from `.prose a` (`#c9a77a` on the page background), which clears 4.5:1. The same selector change keeps those buttons on their own colors.

### 2. `/designs/slate` — light text on a white page, and horizontal scroll at 320px

Not in the sitemap or the header. The route is still built and reachable.

- **1.4.3 Contrast (Minimum), Level AA. Serious.** axe `color-contrast`, 5 nodes, both consent states.

  | Text | Color | Background | Ratio | Required |
  | --- | --- | --- | --- | --- |
  | “Anchor” (`#slate-brand`) | `#f2f0eb` | `#ffffff` | 1.13 | 3:1 (large) |
  | “Family memories…” (`.slate-line`) | `#f2f0eb` | `#ffffff` | 1.13 | 3:1 (large) |
  | Support line (`.slate-support`) | `#c4bfb5` | `#ffffff` | 1.83 | 4.5:1 |
  | “How it works” (`.slate-btn-ghost`) | `#f2f0eb` | `#ffffff` | 1.13 | 4.5:1 |
  | “Get started” (`.slate-link`) | `#c9a77a` | `#ffffff` | 2.26 | 4.5:1 |

- **Cause:** `apps/web/src/pages/designs/slate.astro` loads only `slate.css`. That file sets light colors on `.slate` (`--slate-text: #f2f0eb` and so on) and never paints a page background. The real site is dark because `BaseLayout` also loads `tokens.css`, which sets `body { background: #1a1a1a }`. This standalone page does not.
- **1.4.10 Reflow, Level AA.** At 320×640, `documentElement.scrollWidth` is **374** against a client width of **320**. Offender: `main.slate-main` (about 344px wide). `.slate-main` is `width: 100%` plus horizontal padding, and this page does not get the global `box-sizing: border-box` from `tokens.css`.
- **Fix:** On this page, paint `background: #1a1a1a` (the `--slate-bg` already declared in `slate.css`) and use `border-box` for the shell. Or stop publishing `/designs/*` if these are unused explorations. The live homepage does not have this bug.

### 3. `/designs/ink` — index numbers at 4.41:1

Not in the sitemap. axe `color-contrast`, serious, both consent states.

- **Where:** `.ink-action-index` in `apps/web/src/components/designs/ink/ink.css` (`opacity: 0.55` on the ink color).
- **Measured:** `#787878` on `#ffffff`, 12px, ratio **4.41**. Required **4.5:1**. Three nodes: “01”, “02”, “03”.
- The spans are `aria-hidden="true"`, but they are still visible, so 1.4.3 still applies. If they are only decoration, remove them from the screen; if they stay visible, darken them (about `#767676` is the edge; `#5c5c5c` is a safe margin).

## Checked, and not a failure

### Account creation privacy policy (this commit)

`/family` → **Create an account**. The policy is the full text in `.reg-policy` (`apps/web/src/components/RegisterFlow.tsx`).

- axe: 0 violations, 0 incomplete.
- Contrast walk: no text under 4.5:1 (or 3:1 for large text).
- The region is normal document flow (`overflow-y: visible`, `max-height: none`). People scroll the page. It is not a nested scroller.
- Before the end is on screen, “I have read the Privacy Policy” and **Create account** are disabled, and `#policy-hint` says to scroll. After the end line is in view, both enable and the hint updates. One `h1`. No skipped heading levels. No inputs without a label.
- At 320×640, no horizontal overflow.

### Private chat on `/app`

After the scripted demo, the private `.chat-log` overflows (`scrollHeight` 1330, `clientHeight` 364) and has no focusable children. In headed Chromium 153, Tab still lands on that log, and Page Down moves it (scrollTop 0 → 158). That passes 2.1.1 in this browser. Headless keyboard events did not scroll it; do not treat that as a failure. Optional hardening for browsers that do not focus scroll containers: `tabindex="0"` and an accessible name on `.chat-log`.

### Routes with no axe violations and no contrast failures

`/`, `/app`, `/family` (chooser), `/my-data`, `/privacy`, `/terms`, `/cookies`, `/sitemap`, `/designs/linen`, `/designs/mist`.

`/designs/quiet` has no axe violations. axe marks several text nodes **incomplete** because the page background is a gradient (`quiet.css`). A solid-color walk of the same text did not fail. Ink `#1a1917` on paper `#f2efe8` / `#e8e4db` is well above 4.5:1. Not queued as a fix.

Document language is `en`. Each tested page has a title. The viewport meta does not disable zoom. Public pages include a skip link.

The cookie banner (`#consent-body`) is an axe incomplete contrast result on every page where it is open. The contrast walk, using the banner’s `#111` background, did not fail. Not queued as a fix.

## Notes (not WCAG 2.1 AA failures)

- **Target size.** WCAG 2.1 AA has no 24px or 44px target-size rule (2.5.5 is AAA; 2.5.8 is WCAG 2.2). Inline links in prose are about 18–22px tall. Cookie-banner links are about 22px tall. Signup checkboxes are 20×20 inside labels whose minimum height is `--tap` (2.75rem). Buttons use that same minimum. No change required for 2.1 AA.
- **Signed-out `/my-data` has no `h1`.** `MyDataPanel` renders `TelegramLogin`, whose heading is an `h2` (“Get started with Telegram”). The signed-in view has an `h1`. A missing `h1` is not by itself a 2.1 AA failure. Prefer an `h1` for the page heading when that view is next touched.
- **Design pages** `/designs/linen` and `/designs/mist` had no AA failures in this pass. `/designs/quiet` is the gradient case above. They are still public URLs.

## Suggested order

1. Fix `.prose a` versus `.btn` in `apps/web/src/styles/tokens.css`, then recheck `/how-it-works` and the 404 page.
2. Decide whether `/designs/*` stays public. If it does, fix `/designs/slate` (background and `border-box`) and `/designs/ink` (index contrast).
3. Optionally treat axe color-contrast **incomplete** on `.btn-primary` as a failure in `apps/web/scripts/a11y-check.mjs`, so this button bug cannot go green again.
