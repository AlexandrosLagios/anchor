# WCAG 2.1 AA audit — Anchor website

**Audited:** 2026-09-26  
**Commit:** `0f6dfe73522e44e37c88ba99262c6d3ff9fcd51b`  
**App:** `apps/web` production static build (`astro build`, then `astro preview` on `http://127.0.0.1:4321`)  
**Engine:** axe-core 4.13.0 in headless Chromium (Playwright)  
**Rule tags:** `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa` (WCAG 2.1 Level A and Level AA)

Machine-readable copy: [2026-09-26-wcag-2.1-aa.json](./2026-09-26-wcag-2.1-aa.json)

## Verdict

The repository gate passes. `pnpm a11y:web` (`apps/web/scripts/a11y-check.mjs`) reported **0 violations** on 10 public routes, each with the consent banner open and dismissed.

The site does **not** meet WCAG 2.1 AA. axe files one real contrast failure as incomplete, so the gate stays green. High contrast mode, the scripted demo after a sample line, and one design study fail outright.

| Check | Result |
| --- | --- |
| Gate: 10 public routes × consent open and dismissed | Pass, 0 violations |
| Same routes at 1280×800 and 320×800, plus the accessibility panel open on `/` | Pass, 0 violations |
| High contrast (`html.a11y-contrast`) on those 10 routes | Fail, 173 nodes, all 1.4.3 |
| `/how-it-works` and the 404 primary buttons in the default theme | Fail, 1:1 contrast (axe: incomplete) |
| `/app` after Send the photo → Yes, I’ll take part → A little later → Use a sample line | Fail, 1.4.3 and 2.1.1 |
| Public pages at 320px CSS width | No horizontal overflow |
| Homepage keyboard sample (8 tabs) | Skip link first, 2px solid focus ring |

## Fix later

### 1. High contrast turns brand purple into the text color

**Criterion:** 1.4.3 Contrast (Minimum), Level AA  
**Where:** all 10 public routes when Accessibility → High contrast is on  
**Count:** 173 failing nodes

`html.a11y-contrast` in `apps/web/src/styles/tokens.css` swaps `--background` to `#050316` and `--text` to `#fbfbfe`, and leaves `--primary` at `#443dff`. Links are then painted with `color: hsl(var(--primary))`.

| Pair | Ratio | Nodes | What it is |
| --- | --- | --- | --- |
| `#443dff` on `#050316` | 3.25:1 | 155 | Nav, footer, prose, and auth links. Needs 4.5:1. |
| `#050316` on `#443dff` | 3.25:1 | 7 | Primary buttons. `color: hsl(var(--background))` follows the swapped token, so the label is dark on purple. |
| `#f3f2fe` on `#dddbff` | 1.21:1 | 10 | `/app` step chips (`li > span`), for example “Kept in her words”. |
| `#fbfbfe` on `#dddbff` | 1.29:1 | 1 | `/family` secondary button “Sign in”. Accent fill stays light while text becomes the light contrast color. |

With the panel open on `/` in high contrast, the “Larger” text-size button is an extra failure: `#fbfbfe` on `#dddbff`, 1.29:1, 13.6px bold (`.a11y-widget-scale button`). The widget colors (`--ink`, `--soft-bg`, `--brand` in `AccessibilityWidget.css`) do not follow the contrast theme.

**Later fix:** pick a link and button-label color that stays at least 4.5:1 on the dark surface, and do not reuse the swapped `--background` as the primary-button label. Restyle accent fills (secondary buttons, demo chips, widget scale buttons) for the dark theme. `#443dff` on near-white passes; on `#050316` it does not.

### 2. Primary buttons inside `.prose` have no contrast

**Criterion:** 1.4.3 Contrast (Minimum), Level AA  
**Where:** `/how-it-works` (“Get started”), unknown URLs that render `404.astro` (“Back to Anchor”)  
**Measured:** `color` and `background` both `rgb(68, 61, 255)`. Ratio **1.00:1**. Text is 15px, weight 600, so the requirement is 4.5:1.

**Cause:** `.prose a` in `tokens.css` (specificity 0,1,1) beats `.btn-primary` (0,1,0). Both pages put the buttons inside `<article class="prose">`. Hover looks fine, because `.btn-primary:hover` wins and the label becomes `rgb(251, 251, 254)` on `rgb(47, 39, 206)`.

axe reports this as **incomplete**, message “Element has a 1:1 contrast ratio with the background”, so `pnpm a11y:web` does not fail.

The secondary buttons on those same pages inherit the link color too. They still pass, at 4.66:1 (`#443dff` on `#dddbff`). That is close to the 4.5:1 floor, and it is not the color `.btn-secondary` sets.

Homepage `a.slate-btn-primary` sits outside `.prose` and measures 6.06:1. It passes in the default theme (it fails only under high contrast, item 1).

**Later fix:** set `.prose a.btn`, `.prose a.btn-primary`, and `.prose a.btn-secondary` (including hover) so button colors win over the prose link color.

### 3. Demo, after a sample voice line

**Criteria:** 1.4.3 Contrast (Minimum), Level AA, and 2.1.1 Keyboard, Level A  
**Where:** `/app`, after “Send the photo”, “Yes, I’ll take part”, “A little later — bring it back”, then “Use a sample line”

- `.voice-tag` (“Voice note”) is `#443dff` on `#cbc8ff`, **3.94:1**, 12.48px bold. Needs 4.5:1. Color comes from `var(--brand)` in `MvpDemo.css`.
- The private `.chat-log` (`role="log"`, `overflow: auto`) fails `scrollable-region-focusable`. It is not focusable and has no focusable content, so a keyboard user cannot scroll it. The group log uses the same CSS and will fail the same rule once its content overflows.

**Later fix:** darken the voice tag or lighten that bubble until the ratio is at least 4.5:1. Give an overflowing `.chat-log` a keyboard path (`tabindex="0"` is the usual fix) and a visible focus style.

## Checked, and not a defect

- Consent banner copy (`#consent-body`) is axe incomplete because the fixed banner overlaps the page. Computed text is `rgba(5, 3, 22, 0.72)` on `rgb(251, 251, 254)`, about **8.64:1**. Passes 1.4.3.
- Step numbers on the homepage and the family registration list are axe incomplete only because the text is a single digit and `aria-hidden`. Not a contrast failure.
- Public routes at 320px width do not scroll horizontally (`/`, `/how-it-works`, `/app`, `/family`, `/my-data`, `/privacy`, `/terms`, `/cookies`, `/sitemap`). This is a spot check for 1.4.10, not a 400% zoom review.
- Homepage tab order starts at “Skip to content”, then the wordmark, primary nav, “Get started”, and the hero button. Focus is a 2px solid `#443dff` outline. This is an 8-stop sample, not a full keyboard audit.

## Not tested

- Signed-in `/family` and `/my-data` (the signed-out screens had 0 violations in the default theme).
- A full keyboard walk, screen reader pass, or 400% zoom review.
- Telegram’s login window. The site only supplies the button that opens it.
- Text size 125% and 150%, grayscale, and the other accessibility toggles, except high contrast as above.
