How Anchor works

A 10-minute technical read. Written from the code on main at commit 40fb18a, 26 September 2026. The live bot runs revision anchor-bot-00016-xdv (commit c7e3b96), which holds every change described here.

In one breath. Anchor is a Telegram bot that lives in a family's group chat. When someone shares a moment worth keeping, Anchor saves it in that person's own words and reacts with ❤. Later it brings moments back: to the whole group at 18:00, and in private at 11:00 to each member who asked for them. People talk to it in plain language, can hear every answer as a voice note, get reminders offered from the family's own messages, can forward a suspicious message for a second opinion, and can take a phone call in which Anchor reads them a moment, records their story, and connects them to the person who shared it. Underneath, it is one Node process on Cloud Run: a Telegram long poll, a 2-second timer, thirteen feature modules, one JSON file as the database, and OpenAI for every judgement call.

1. The pieces

anchor-bot pulls updates from Telegram with a long poll, so Telegram never needs to reach it. The service opens to the internet for one purpose: the audio stream that Twilio sends during a phone call.

The website and its API share the repository with the bot, and the same Nest codebase, but they run elsewhere and store their data elsewhere. Section 13 covers them briefly.

2. Two loops and a router

Two loops drive the bot. family.service.ts starts both when TELEGRAM_BOT_TOKEN is set.

  • The poll. A getUpdates long poll that takes one update at a time, so a restart repeats at most the update in flight. Each update becomes one normalized Incoming event (a text, a photo, a voice note, a button tap) and goes to the router.
  • The tick. Every 2 seconds, each feature of each family gets the demo-clock window since the previous tick. Everything scheduled happens here: closing a bundle of messages, the 18:00 memory, a due reminder, fading an old offer. Each feature runs in its own try/catch, so one failure never stops the rest.

The router offers each event to thirteen features in a fixed order, and the first one that returns true owns the event.

#FeatureWhat it owns
1introAnchor joining a group, which creates the family
2fastforwardThe stage time machine
3forget"Anchor, forget this" and "Anchor, don't bring this back"
4remindersReminder offers from group messages, and their delivery
5scamsMessages that a member forwards to Anchor in private
6membersJoining, the choices screen, the phone number, "stop"
7invitationsPrivate replies to a moment Anchor sent
8memoriesThe 18:00 memory, /memory, and stories told as replies
9intents"Anchor, …" in the group, and any unclaimed private message
10captureEvery other group message: bundling and saving moments
11shares"Shall I send this to Sofia?" after a save
12echoes"Then and now" pairs
13callsReminder calls and the daily call

Two features bend the rule on purpose. reminders and members can act on a group message and still return false, so capture sees the same message. Features reach Telegram only through a small Transport interface. The tests plug in an in-memory FakeTransport, and a WhatsApp version of Anchor would be one more implementation.

3. The record: one JSON file

The bot has no database. Its whole state is one object, { clockStart, clockOffset, families[] }, in one JSON file. core/types.ts defines all of it in about 170 lines, and it is the best first file to read.

  • Each save writes a temporary file and renames it over the real one, so a crash never leaves half a file. A file that does not parse at boot moves aside as .corrupt-<time>, and the bot starts empty.
  • There are no migrations. When v2 changed the shape, the loader started filling defaults for older records.
  • On Cloud Run, the file sits in a Cloud Storage bucket mounted at /data. The mount has no locking, and a rollout runs two instances side by side for 10 to 16 seconds, so the last write wins. Deploys happen while the family is quiet.

Anchor keeps only the moments it chooses and drops every other message. There is no chat archive.

4. A clock you can fast-forward

demoNow = clockStart + (realNow − clockStart) × 86400 / ANCHOR_DAY_SECONDS + clockOffset

The live bot runs at real speed (ANCHOR_DAY_SECONDS=86400). A local run with 120 lives a day every two minutes. Two slots shape the day, on Athens time: 11:00 for private invitations and the daily call, 18:00 for the group memory. slotIn(window, hour) returns the latest hour:00 inside (from, to], so consecutive windows fire each slot once.

On stage, /fastforward 7 jumps seven days, and /fastforward 08:05 jumps to the next 08:05. Both add to clockOffset. The clock-time form also empties the next tick window, so the 11:00 and 18:00 slots inside the jump stay quiet while a due reminder still fires. The offset is global and permanent, which is why rehearsals run on the dev bot.

5. From a message to a moment

  1. Rules in code. Stickers, GIFs, documents, polls, forwarded messages, commands, and link-only texts drop out first.
  2. Bundling. People send a photo, then a caption, then "and she loved it!". Messages from one sender within 5 minutes form one bundle, and a new photo from outside the same album starts the next one. A bundle with a picture and words closes on the next tick, and any other bundle closes after 5 quiet minutes. Albums get 3 seconds of grace, because Telegram delivers them one item at a time.
  3. A free filter. No picture, no voice note, and fewer than 3 words means no model call.
  4. One model call gets the texts, the first photo, and any voice note. For a video it gets the thumbnail, because a bot can download at most 20 MB. It returns a verdict (family_moment, sensitive, logistics, small_talk), a salience from 1 to 5, the people, an event date, a title, up to 5 tags, a transcript, and a description of the picture. The prompt lists the family's existing tags, so "Lucy" stays "Lucy" across months.
  5. Save and react. Family moments and sensitive moments are saved, and Anchor reacts with ❤. Everything else only increments a counter.

The rule behind every line: the model never speaks for a person. moment.text holds the sharer's own words, verbatim, and the model supplies only metadata. Code builds every quote, for example Eleni shared: «Maria's first day of school!». A photo with no words becomes Eleni shared a photo: Mapo tofu at home, so a model-written title never passes as anyone's words.

The description follows the same rule from the other side. It is Anchor's own sentence for a member who cannot see the picture well, such as "The photo shows a girl with a red backpack at a school gate." It never names a person or a pet, never guesses a feeling, and code drops any description that does not open with "The photo shows" or "The video shows". Only the voice says it: the invitation voice note and the phone call.

A sensitive moment (a loss, grief, illness) stays in the record, and Anchor never brings it back on its own. A reply of "Anchor, forget this" deletes a moment, and "Anchor, don't bring this back" marks it sensitive.

6. Bringing moments back

To the group, at 18:00

Each family gets at most one memory a day. A moment is due 7, 30, and 365 days after it was saved, and on the anniversary of its event date. Anniversaries win, then higher salience, then older moments.

  • Collections. When other moments share the picked moment's most common tag, the memory becomes an album of up to 6 photos, oldest first. A fast model call writes the caption (at most 160 characters, no invented facts or feelings), and a fixed caption covers a failed call. "Anchor, I want a memory of Lucy" gathers every moment about Lucy.
  • Then and now. Each new moment gets one call that asks whether an older moment from someone else shows the same kind of life event, such as two first days at school. A match posts both, the earlier one first.
  • Stories. A reply to a memory post with a voice note or at least 3 words becomes a story on that moment.

In private, at 11:00

Members who turned on "Family moments" get at most one invitation a day: the photo, then a voice note that says "Eleni shared: «…» The photo shows … What does it remind you of?". Anchor makes the clip once per moment and reuses it by its Telegram file id.

Returns are spaced like flashcards, minus the quiz: after 1, 2, 4, 8, 16, then 32 days, with at most 7 deliveries per moment. A delivery counts whether or not the member answers. Anchor never reads silence as forgetting.

A reply is read as a story, unsure ("a school?"), a question ("who is that?"), or other ("ok"), and code decides short questions without a model call. A story gets "Shall I share it with the family?", and only a yes posts it in the group, with a mention that notifies the person who shared the moment.

7. No commands

v2 dropped the command list. The intents feature reads each group message that starts with "Anchor," and each private message that no other feature claimed, in two stages.

  1. Fixed phrases, in code. A regex catches "send me", "another moment", "settings", "call me", "what did I miss", and "stop", so the key demo phrases never depend on the model.
  2. One model call returns { intent, momentId, momentIds }. The intent is an enum of ten, and the moment ids are an enum of the family's non-sensitive moments, so the model can pick only a moment that exists. Code validates both anyway. An invalid answer or a failed call becomes unclear, which replies with "here is what I can do" and buttons.

The newest addition lets people ask for a memory without "Anchor,". To stay out of ordinary family chat, such a message reaches the model only when it holds a memory word (memory, photo, album, and a few more), names a person or a tag that the record knows, and is neither a reply to someone nor forwarded. Even then, Anchor answers only when the model reads a memory request. In a replay on the live family record, 10 of 12 requests got their album, and 0 of 14 ordinary messages got a reply.

Code picks the buttons under each private answer ("Send me a moment", "What did I miss?", "My settings", "Call me"). The model never does.

8. Members, choices, and offers that fade

Joining. Telegram lets a bot write to someone in private only after that person taps Start. Anchor's buttons link to t.me/<bot>?start=<family id>. Anyone could forward that link, so a newcomer joins only when getChatMember confirms they are in the group right now. Each member then picks what Anchor sends them:

ChoiceDefaultEffect
Family momentsoffThe 11:00 invitations. Nothing arrives unasked before this yes.
RemindersonReminder offers, each still one tap away from a no.
Share offerson"Shall I send this to…?" after you post.
VoiceoffEvery private line arrives as a voice note.
Phone callsoffCalls, after a one-tap phone number share.
  • Ephemeral messages. Nudges and offers are group messages that only one member can see, a recent Bot API feature. They need Anchor as an admin of a supergroup, and Telegram does not guarantee delivery to someone offline, so nothing important depends on them.
  • Share offers. When Eleni's photo is saved, only Eleni sees "Shall I send this to Sofia now?". A yes sends it to Sofia at once.
  • Reminder offers. A regex gate (remember, remind, tomorrow, in the morning, a clock time) decides which texts reach a fast model call. The call returns { offer, who, time }, and who is an enum of member ids plus unknown. Unknown means no offer, so a reminder for someone else never lands on the sender. A reply is how "Mum" becomes Sofia: the prompt names the member being replied to. Sofia taps a time, Eleni's message gets a ✍, and the reminder arrives in private when it is due. The family sees only the ✍.
  • Fading. An unanswered offer disappears after 10 demo-clock minutes, and "Stop offering this" turns that kind of offer off.
  • The scam shield. A member who gets a suspicious message can forward it to Anchor in private. Anchor checks only what a member forwards to it. One fast call answers two questions: does the message ask for money, a gift card, a code, or bank details, and which member does it claim to come from (an enum of member ids, or none). The prompt tells the model that the message is data and never instructions. Telegram's forward origin tells Anchor which account sent the message, when the sender does not hide it. A money request that did not come from the claimed member's own account gets a warning to call that person on the number you know, and a "Tell Eleni" button that lets Eleni know someone used her name. Anchor never says a message is certainly a scam or certainly safe.
  • Voice both ways. Every private line goes through tell(). For a member who chose voice, the text goes to TTS, ffmpeg turns the WAV into OGG Opus, and the text rides along as the caption. A failed TTS call sends the text. A 403 from a private chat means the member blocked Anchor, and Anchor stops writing.

9. The phone call

Twilio places the call and OpenAI Realtime is the voice. The bot sits in the middle, because it has to hear the audio to cut out the member's story afterwards.

  1. Trigger. "Call me", a reminder for a member who turned calls on, or the 11:00 daily call (once a day at most, and only when the family shared something new).
  2. Dial. One Twilio Calls API request with inline TwiML, <Connect><Stream url="wss://…/call/stream">, and a random single-use token. The Twilio number's configuration never changes.
  3. Bridge. The Nest server upgrades /call/stream to a WebSocket, drops any stream whose token Anchor did not issue, and opens a second socket to OpenAI Realtime (gpt-realtime-2.1). Both sides speak G.711 μ-law at 8 kHz, so audio passes through untouched.
  4. Script. The opener ("Hello Sofia, this is Anchor… I'm not a person", the reminder in Eleni's words, then the moment) goes out as "say exactly these words". The bridge ignores the caller until the opener has played, so a "Hello?" at pickup never cuts it off. Then the model listens, asks at most one follow-up that invites and never tests, asks whether to share, and asks whether to connect the member to the sharer. When the member talks over Anchor, the bridge cuts Anchor's audio.
  5. End. The model calls an end_call tool with the answers (share: voice, words, or no, plus tell_sender and connect), and the bridge hangs up after the goodbye. A call lasts at most 10 minutes.
  6. After. The story is the member's side only, cut before the share question, so "yes, share it" never reaches the clip. Sentences like "I don't remember" drop out, and a story that lost a sentence goes out as words only, because the voice would still say it. The audio becomes a voice note for the member, and the group post reuses its file id.

The warm handoff. Every call ends with a way to reach a person. When the sharer has a phone number on file, Anchor asks "Shall I connect you to Eleni now?", says goodbye, and moves the live call to Eleni's phone with a <Dial>, which also takes Anchor out of the call. When Eleni does not pick up within 20 seconds, the group gets "Eleni, Sofia would love a call from you 💛". Without a phone number for the sharer, Anchor asks whether to tell the sharer instead.

Security. Twilio's WebSocket needs a public service. ANCHOR_BOT_ONLY=true makes the process answer 404 to every request except GET /, the stream upgrade, and the /web/* API of the website, so the old prototype routes stay unreachable.

10. The model layer

Features call four functions from model/model.ts: ask (JSON that matches a schema), transcribe, speak (WAV), and valid. OpenAI sits behind them by default, and Gemini is one environment variable away (ANCHOR_MODEL_PROVIDER).

  • OpenAI. Strict JSON-schema output on gpt-4.1-mini, with gpt-4o-mini as the fallback on a 429 or 503. Chat input does not take Telegram's OGG voice notes, so audio goes through gpt-4o-mini-transcribe first. TTS is gpt-4o-mini-tts, asked to sound "warm, calm and slow, like a kind family friend talking to a grandparent".
  • Cache. Every answer is cached on disk under a hash of the prompt, the schema, and the media. It began as a way around a free-tier limit of about 10 TTS requests a day.
  • Trust nothing. Every answer passes a validator in code, and every call has a fixed fallback. A failed classification drops the bundle, so nothing that skipped the sensitivity check enters the record. A failed intent becomes "unclear", a failed reminder call makes no offer, and a failed TTS call sends text.

Every chat line comes from core/lines.ts. The model's own words reach the family in two places only, the album caption and the phone conversation, and instructions fence in both. Prompts go to OpenAI's global API, so they may leave the EU, and the privacy page says so.

11. Telegram lessons

  • The 28-second stall. While the long poll waited, every other Bot API call through Node's global fetch queued behind it. The poll now has its own HTTPS agent, and the same calls take 0.06 to 0.23 seconds.
  • One poller per token. A second process gets a 409. The live bot and the dev bot have separate tokens, and a few 409 lines during a rollout are normal.
  • File ids travel. A file id belongs to the bot, not to a chat, so a voice note uploaded in private goes to the group without a second upload.
  • A known gap. Promoting a bot that is already in a group sends no "joined" event. To create the family, remove Anchor and add it again.

12. Shipping it

  • Cloud Run. anchor-bot in europe-west1 runs one instance (min and max 1, because only one process may poll), with the CPU always on, so the poll and the tick keep running. 1 vCPU and 512 MiB cost about 1.64 USD a day at list price. The image is node:20 plus ffmpeg, and the secrets come from Secret Manager.
  • Deploy. pnpm deploy:bot runs only on a clean origin/main. It runs the tests, builds for linux/amd64, tags the image with the commit, and rolls out a new revision that keeps the flags, secrets, and volume. A person runs it: the lab project gives nobody IAM admin and blocks service-account keys, so GitHub Actions cannot deploy.
  • Tests. pnpm nx test api runs 610 Vitest cases with no network calls, against FakeTransport with the model mocked. demo-flow.test.ts walks the whole demo script. There is no CI.

13. The website and the old prototype

apps/web is an Astro and React site on Vercel with the landing page, sign-up, and an interactive demo. Its API, anchor-api, is the same Nest codebase on Vercel, with JWT auth, Neon Postgres, and Vercel Blob. That API also holds the team's first engine, a WhatsApp flow built around questions and hints. The bot left that framing behind, never touches Postgres, and stays asleep on Vercel, because Vercel never sets the Telegram token.
